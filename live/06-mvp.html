Goal of the MVP: prove that a stranger, matched in under 15 seconds, produces a ten-minute conversation good enough that 45% of users come back within a week. Nothing else matters yet.

Non-goal: proving the business. Conversion is measured, not optimised, in the first release.

1. Scope: what ships in v1

Area In v1 Detail
Onboarding ✅ 5 taps, median < 60s to first audio (02 §1.1, 08 §4)
Age gate ✅ 18+ hard block
Verification ✅ Phone before room 1; liveness before room 3
Matching ✅ 1:1 only, one pair at launch, 10s fallback
Rooms ✅ 1:1 audio, mute, leave, connection state
Prompts ✅ 3 prompts per topic, 4 topics
Speaking balance ✅ Meter only, no enforcement
Correction cue ✅ Correct my Spanish → one cue in ~2s → dismissible card
Recap ✅ Time, 1 fix (free) / 2 fixes + next step (paid)
Report / block ✅ Ends first, 3 options, evidence buffer
Paywall ✅ 20 min/day cap, Plus and Career
Themes ✅ Dark + light, system default
Accessibility ✅ AA, dynamic type to 200%, screen reader labels
Group tables ❌ v1.1, gated on 1:1 P90 ≤ 15s for four consecutive weeks
Live translation ❌ v1.2; v1 ships tap-a-word gloss only
AI partner ⚠️ Limited 5 min/day, both directions of the launch pair, speech-to-speech; labelled, never claims to be human
Interview rooms ⚠️ Content only 6 scripted interview scenarios, no rubric scoring
Streaks / nudge ✅ Weekly goal, one notification, off by default

Launch language pair (deliberate, not aspirational): English ↔ Spanish only, in one time-zone corridor (Mexico City / Guadalajara / Monterrey ↔ Austin / Houston / Dallas), 18:00–23:00 local. A second pair (English ↔ Portuguese) arrives at W12 only if P90 match stays ≤ 15s at peak. Adding a pair halves liquidity; adding four at launch guarantees four empty queues.

2. The cut list (and why each cut is safe)

Cut Why it is safe to cut When it comes back
Group tables 1:1 is the product thesis; tables are a liquidity tool, and liquidity is the thing we do not have yet v1.1, after matching P90 < 20s
Full-duplex AI partner Expensive, and a half-good AI partner teaches users the product is fake v1.2, only if AI fallback rate > 25%
Live translation Kills the learning (people read instead of speak); gloss covers the failure case v1.2
Video Bandwidth, moderation, and it changes the product into a call with a stranger Not planned
Profiles, followers, feeds Explicitly against the thesis Never
Android tablets / iPad layouts < 4% of expected usage; phone-first v1.3
8 languages Liquidity, not engineering One pair per quarter, gated on P90 match time
Human-reviewed mocks Not this product; it is the other plan's feature Never
Recording / replay Consent complexity before trust exists Never by default
B2B / campus dashboards Sales motion before retention M18+

The rule behind the cut list: anything that adds a second user type, a second content type, or a second queue is cut. The MVP has exactly one of each.

Week Engineering Design Exit criterion
1 Repo, auth, design tokens, CI, analytics skeleton Design system in code; room + onboarding hi-fi Components render on both platforms
2 Onboarding 5 taps, age gate, OTP scaffold Matching-screen mic check, post-call level UX A user can reach first audio in < 60s
3 Phone OTP + device attestation; liveness scaffold Report flow (ended → 3 options), safety copy Phone-verified user can enter a queue
4 Match service v0: pair graph, Redis queue, level band Matching states, truth-telling copy Two test devices match each other
5 LiveKit rooms, mute/leave, reconnect, connection quality Room screen final, balance meter 10-minute call with < 1% drop
6 Presence, speaking detection, prompts, timer Prompt card, correction flow Balance meter is accurate ±5%
7 Correction cue end-to-end, gloss, caption strip (optional) Recap layout, word bank A correction arrives as a chip in < 2s
8 Recap, weekly streak, notifications, paywall Paywall, settings, word bank Free cap enforced without interrupting a call
9 Report pipeline, evidence buffer, moderation console v0 Admin console (functional, not pretty) A report reaches a human in < 5 min
10 Closed beta hardening, crash fixes, store builds App Store screenshots, safety copy review 200 users, 1 pair, 18+

Dependencies that can slip and what they block:

Dependency Blocks Fallback
LiveKit (or Daily/Agora) contract Everything in week 5+ Ship 1:1 on a second vendor behind a flag; abstract the SFU interface in week 1
Verification vendor approval Liveness before room 3 for every user Manual review queue for beta users only
Liveness check accuracy Minor-safety guarantee Manual spot-check of 10% of verifications
Deepgram captions Caption strip, correction cue transcription Correction cue degrades to manual text entry

4. Release gates

The build is not "done" when it compiles. It ships when all of these are true:

Gate Threshold Owner
Crash-free sessions ≥ 99.5% over 14 days Eng
P50 time-to-match ≤ 8s (1 pair, peak hours) Eng + Growth
P90 time-to-match ≤ 15s (1 pair, peak hours) Eng
Call setup success ≥ 97% Eng
Audio MOS (self-reported "could you hear clearly?") ≥ 4.2 / 5 Eng
Verification pass rate ≥ 85% first attempt Trust & Safety
Report → human review P1 ≤ 4h, all ≤ 24h (P95) Trust & Safety
Accessibility AA on room + onboarding, VoiceOver/TalkBack pass Design
Safety copy Legal review of the three claims in 04 §9 Legal
App store 18+ rating, no location permission, mic string reviewed PM
